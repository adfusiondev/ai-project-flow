## Purpose

The Architecture skill is used to define the simplest technical architecture that can support the approved MVP.

## Rules

- Start from the requirements, not from a preferred framework.
- Avoid overengineering.
- Do not add backend, database, or infrastructure without a real requirement.
- Keep the architecture portable and maintainable.
- Record important technical decisions.

## Output

Create or update:

- `docs/ARCHITECTURE.md`.
- `docs/DECISIONS.md` when important choices are made.

## Quality gate

Architecture is ready when:

- It supports the current MVP.
- Responsibilities are clear.
- Unnecessary complexity is avoided.
- Important decisions are documented.
