## What it is

`docs/MVP.md` defines the smallest useful first version of the project: its goal, its scope, what is deliberately out of scope, and its success criteria.

## Why it exists

An explicit MVP keeps the first version small enough to finish and verify. It prevents the project from growing silently during implementation.

## When it should be created

After discovery and project context are complete, before requirements are written.

## When it should be updated

- When the MVP goal or scope changes.
- When a feature previously deferred becomes part of the MVP.
- When the success criteria need to be refined.

## What it should contain

- MVP Goal.
- MVP Scope.
- Out of Scope.
- MVP Success Criteria.

## Practical example

This repository's `docs/MVP.md` defines a documentation-focused MVP that includes lifecycle explanations, project file documentation, examples, commands, prompts, and copyable content — and excludes backends, databases, user accounts, and dynamic project generation.
