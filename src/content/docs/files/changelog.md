## What it is

`CHANGELOG.md` records meaningful changes to the project over time.

## Why it exists

Projects are continued by different agents over time. If a change is not recorded, a future agent may repeat it, reverse it, or not understand why it exists.

## When it should be created

At the start of the project, alongside the other core project files.

## When it should be updated

- After a meaningful change.
- After a phase is completed.
- When important decisions are made.

## What it should record

- New features and completed phases.
- Important implementation details.
- Verification results.
- Known issues and limitations.
- Decisions made.

## Practical example

This repository's `CHANGELOG.md` records the creation of the project structure, the completed planning phases, the design system implementation, and the decisions made along the way.
