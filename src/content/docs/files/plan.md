## What it is

`PLAN.md` is the implementation plan. It breaks the project into phases and records each phase's objective, scope, tasks, acceptance criteria, verification steps, and status.

## Why it exists

A written plan makes it possible for any agent — including a future one without conversation history — to know where the project is, what is done, and what comes next.

## When it should be created

After the requirements and architecture are complete, before implementation begins.

## When it should be updated

- After a phase is completed.
- When the plan changes.
- When the next step changes.

## What each phase should include

- Objective.
- Scope.
- Tasks.
- Acceptance criteria.
- Verification.
- Status.

## Practical example

This repository's `PLAN.md` defines phases from planning foundation through design system implementation to core content, copy interactions, localization readiness, verification, documentation reconciliation, and handoff.
