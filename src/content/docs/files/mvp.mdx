## Purpose

A written agreement on the smallest version that is worth building and verifying first — so the first version stays small enough to finish, and scope creep becomes visible.

## When to use it

**Required** for Standard and Advanced projects; **optional** for Small.

- **Create** — right after discovery and `PROJECT_CONTEXT.md`, before requirements.
- **Update** — when the MVP goal, scope, or success criteria change.
- **Skip** — only when the project is so small that the scope is obvious without writing it down.

## Required inputs

- The project purpose and primary user, from `PROJECT_CONTEXT.md`.
- The smallest useful feature set.
- What is explicitly out of scope.
- Success criteria for the first version.

## Reads from and feeds into

- Reads from `PROJECT_CONTEXT.md` and agreed decisions.
- Feeds into `docs/REQUIREMENTS.md` (the scope boundary) and `docs/DECISIONS.md` (scope decisions).

## Example

For a personal notes app: goal — save and search notes offline; scope — create, edit, delete, and search notes; out of scope — sync, accounts, and reminders.
