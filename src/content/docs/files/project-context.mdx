## Purpose

A single source of truth for the project's purpose, primary user, product form, current MVP, and core rules — so the repository explains itself without the original conversation.

## When to use it

- **Create** — at the start of a project, right after discovery.
- **Update** — after a meaningful change in purpose, scope, MVP, product form, or rules.

## Required inputs

- Project purpose and the primary user.
- Current product form and MVP scope.
- Future scope, separated from the MVP.
- Core project rules and constraints.

## Reads from and feeds into

- Reads from the discovery stage and from agreed decisions.
- Feeds into `PLAN.md`, `PROJECT_STATUS.md`, `AGENTS.md`, and every prompt generated in the Prompt Generator.

## Example

For a small docs project, `PROJECT_CONTEXT.md` would start with:

- **Project purpose** — a bilingual reference website for an AI-assisted workflow.
- **Primary user** — the project owner.
- **Current MVP** — reference pages with copyable content; no backend.
- **Core rule** — keep content reusable and free of long duplicated prompts.
