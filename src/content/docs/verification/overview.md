This section explains how to verify implementation before marking work as complete.

Verification is the difference between claiming work is done and knowing it is done. It compares the real result against documented acceptance criteria rather than trusting intent.

## Pages in this section

- [Verification Workflow](/verification/workflow/) — the checks to run and when.
- [Build and Runtime Checks](/verification/build-and-runtime/) — how to verify the project builds and runs.
- [Acceptance Criteria Review](/verification/acceptance-criteria/) — how to review work against the documented criteria.

## The core rule

A task should only be considered complete when:

- The implementation exists.
- The relevant build or runtime checks pass.
- Required functionality has been tested.
- Acceptance criteria have been reviewed.
- Important regressions have been checked.
- Documentation has been updated where needed.
