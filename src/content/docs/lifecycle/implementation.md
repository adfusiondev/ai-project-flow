Implementation is where the project is actually built, following the phases defined in the plan.

## What this stage is

This stage executes each implementation phase: reading the relevant requirements and architecture, writing the code or content, running the relevant checks, and confirming the phase's acceptance criteria before moving on.

## How to work during implementation

- Change only what the current task requires.
- Preserve existing functionality unless the task explicitly changes it.
- Avoid introducing unnecessary dependencies.
- Follow the documented design system and shared patterns.
- Reuse shared patterns instead of creating page-specific duplication.
- Verify work before marking it complete.

## What to do before each meaningful change

- Identify the current phase.
- Read the relevant requirements.
- Read relevant architecture decisions.
- Confirm what is in scope and what is out of scope.
- Identify acceptance criteria.
- Identify the files likely to be affected.

## What should be completed before moving on

- The implementation exists.
- The relevant build or runtime checks pass.
- Required functionality has been tested.
- Acceptance criteria have been reviewed.
- Documentation has been updated where needed.

Move to **Verification and Testing** after each phase is implemented.
