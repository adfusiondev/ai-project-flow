Implementation planning converts requirements and architecture into an ordered set of phases that can be executed and verified.

## What this stage is

This stage produces `PLAN.md`, which describes each implementation phase, its scope, its tasks, its acceptance criteria, and its status.

## Why it matters

A written plan makes it possible for any agent — including a future one without conversation history — to know where the project is, what is done, and what comes next.

## What each phase should include

- Objective.
- Scope.
- Tasks.
- Acceptance criteria.
- Verification steps.
- Status.

## Rules to follow

- Break the project into meaningful phases.
- Keep each phase focused.
- Define acceptance criteria for every phase.
- Do not mix future scope into the current plan.
- Keep phase status visible.

## What should be completed before moving on

- `PLAN.md` exists.
- Phases are clear and ordered.
- Each phase can be verified.
- The current phase is identifiable.
- The next step is explicit.

Move to **Skills and Agent Instructions** when the plan makes the next step obvious.
