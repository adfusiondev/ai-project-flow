Project status updates keep the repository's record of what has been done, what is in progress, and what remains.

## What this stage is

After meaningful changes, `PROJECT_STATUS.md` is updated so the current phase, completed work, pending work, known issues, blockers, and next recommended step are always visible.

## Why it matters

Any agent or human opening the repository should be able to quickly determine where the project is. Status files make the project self-explaining without requiring conversation history.

## What the status should include

- Current phase.
- Overall status.
- Completed work.
- In progress work.
- Pending work.
- Known issues.
- Blockers.
- Next recommended step.

## Rules to follow

- Reflect the actual repository state.
- Do not mark work complete before verification.
- Keep the next step explicit.
- Update status after meaningful project changes.

Move to **Change Documentation** after the status reflects the real state.
