After discovery, the agreed understanding is written down as the project's permanent context.

## What this stage is

Project Context turns the discovery outcome into `PROJECT_CONTEXT.md`, a repository file that any human or AI agent can read to understand what the project is and how it should be treated.

## Why it matters

Conversation history is not a reliable source of truth. The repository itself must explain the project so it remains understandable across different IDEs and AI agents.

## What the file should contain

- Project purpose.
- The primary user.
- The current product form.
- The current MVP and its scope.
- Future scope separated from the MVP.
- Content structure.
- Design references and constraints.
- Languages and localization direction.
- Portability goals.
- Core project rules.

## What should be completed before moving on

- `PROJECT_CONTEXT.md` exists and matches the discovery outcome.
- The MVP scope is separated from future ideas.

## When it is complete

Move to **MVP Definition** when the project context file clearly explains the project without requiring prior conversation history.
