# Project Discovery Skill

## Purpose

Use this skill to understand and clarify a software project idea before defining the MVP, requirements, architecture, or implementation plan.

The goal is to reduce assumptions and create enough shared understanding to document the project correctly.

---

## Use This Skill When

Use this skill when:

- Starting a new project.
- The project idea is vague or incomplete.
- Important product decisions are still unknown.
- The user asks for planning before implementation.
- Existing documentation does not clearly explain the project purpose.
- A project is being recovered and its original intent is unclear.

---

## Core Rule

Do not begin implementation during discovery.

Discovery exists to understand the project before deciding how to build it.

---

## Discovery Questions

Clarify only the questions that materially affect the project.

### Project Purpose

Determine:

- What is being built?
- Why does it exist?
- What problem does it solve?
- What outcome should it produce?

### Primary User

Determine:

- Who will use the project?
- Is it personal, internal, public, or commercial?
- Are multiple user roles required?

Do not invent public-user requirements when the project is personal.

### Product Form

Determine whether the project is currently:

- Documentation site.
- Landing page.
- Web application.
- Desktop application.
- Mobile application.
- API.
- CLI.
- AI tool.
- Other software product.

### Platform

Determine relevant target environments such as:

- Browser.
- Windows.
- macOS.
- Linux.
- Mobile.
- Local-only.
- Cloud-hosted.
